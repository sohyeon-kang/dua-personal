# DUA — 부산 지하철 여행 도우미

> 어디로든 떠나고 싶은 순간, 부산이 답합니다.

DUA는 **부산을 처음 방문하는 국내 여행객을 위한 지하철 중심 여행 서비스**를 목표로 하는 프로젝트입니다. 부산역을 출발 거점으로 삼아 지하철 이동, 환승과 출구 안내, 맛집과 관광지 추천을 하나의 여행 동선으로 연결하고자 합니다.

현재 코드는 **지역·동행 유형·날씨에 따른 장소 추천과 지도 표시를 구현한 웹 프로토타입**입니다. 지하철 길찾기, 시간대별 추천, 저장한 장소 기반 경로 생성은 향후 구현할 기능입니다.

## 기획 배경

초행 여행객은 목적지까지 가는 방법뿐 아니라, 이동 과정에서 무엇을 확인해야 하는지와 도착 후 어디를 방문할지도 함께 알아야 합니다. 이 프로젝트는 다음과 같은 불편을 해결하는 데서 출발했습니다.

| 구분 | 해결하고자 하는 불편 |
| --- | --- |
| 지하철 이용 | 환승 위치와 빠른 환승 정보가 부족해 이동이 어려움 |
| 출구 선택 | 관광지와 가까운 출구와 출구 이후의 경로를 파악하기 어려움 |
| 열차 운행 이해 | 급행·일반, 직행 여부, 중간 종착에 따른 하차와 재승차 안내가 필요함 |
| 관광지 탐색 | 여행 조건에 맞는 맛집·카페·명소를 찾기 번거로움 |
| 일정 구성 | 방문할 장소의 순서와 이동 동선을 직접 정해야 함 |

위 내용은 프로젝트의 문제의식이며, 특정 지도·도시철도 앱의 기능을 검증한 비교 결과는 아닙니다.

## 대상과 활동 범위

- **대상:** 부산이 낯선 국내 여행객. 초기 기획에서는 외국인 대상 다국어 기능을 범위에 포함하지 않습니다.
- **지역:** 서면, 광안리, 해운대 등 부산의 주요 관광 거점.
- **이동 기준:** 부산역을 출발 거점으로 하는 지하철 이동과 출구 이후 도보 연결.
- **교통수단:** 지하철 중심으로 구성하며 버스 경로는 초기 범위에서 제외합니다.
- **장소:** 팀에서 함께 선정한 식당, 카페, 관광지 등을 조사하고 추천 데이터로 정리합니다.

## 목표 기능

| 기능 | 제공하려는 정보와 경험 |
| --- | --- |
| 열차 이용 안내 | 적용 대상 노선의 급행·일반 구분, 직행 여부, 중간 종착 시 하차·재승차 설명 |
| 빠른 환승 안내 | `8-1`과 같은 승강장 탑승 위치를 기준으로 환승 경로 안내 |
| 출구 중심 경로 | 목적지와 가까운 출구와 출구에서 추천 장소까지의 도보 경로 제공 |
| 관광 코스 추천 | 맛집·카페·명소를 방문 순서와 함께 추천 |
| 시간대 기반 추천 | 노을 감상, 드론쇼 등 방문 시각이 중요한 활동을 일정에 반영 |
| 개인 맞춤 동선 | 사용자가 가고 싶은 장소를 저장하면 해당 장소를 연결하는 경로 생성 |

열차 유형과 운행 안내는 실제 서비스 대상 노선에 해당하는지 확인한 뒤 적용합니다. 행사 일정과 운영 정보 역시 확인된 데이터를 바탕으로 반영할 예정입니다.

## 차별화 방향

기존 지도·도시철도 앱과 비교할 때 DUA가 지향하는 차별점은 **여행 일정과 지하철 이동을 함께 설계하는 경험**입니다.

- **여행 중심 정보:** 이동 안내에 환승 위치, 출구, 주변 관광 정보를 함께 제공합니다.
- **이동과 관광의 연결:** 부산역에서 관광 지역으로 이동하고, 출구에서 개별 장소까지 이어지는 동선을 구성합니다.
- **시간과 상황 반영:** 동행 유형·날씨에 더해 방문 시간과 행사 일정을 추천에 반영합니다.
- **사용자가 선택하는 여행:** 추천 코스를 비교하거나 가고 싶은 장소를 저장해 자신의 일정을 구성하도록 합니다.

### 현재 사용자 흐름

1. 검색 화면에서 지역, 동행 유형, 날씨를 선택합니다.
2. 백엔드에 선택 조건을 전달해 추천 코스를 요청합니다.
3. 결과 화면에서 코스별 장소를 확인하고 탭으로 비교합니다.
4. 지도에서 장소 위치와 코스 연결선을 확인하도록 구성되어 있습니다.

### 추천 방식

1. 주소에 선택 지역의 문자열이 포함된 장소를 추립니다.
2. 동행 유형과 날씨에 관련된 데이터의 키워드로 가산점·감점을 계산합니다.
3. 식당 → 카페 → 소품샵 순서로 후보를 선정하며, 두 번째 장소부터 이전 장소와의 직선거리에 따른 감점을 반영합니다.
4. 각 단계에서 정렬된 상위 최대 6개 후보 중 하나를 무작위로 선택합니다.
5. 한 번의 요청에서 이미 선택한 장소 ID를 공유해 세 코스 사이의 장소 중복을 피합니다.

같은 조건으로 검색해도 결과가 달라질 수 있습니다. 지역별·카테고리별 장소가 부족하면 일부 코스가 짧거나 비어 있을 수 있습니다. 현재 추천은 키워드와 거리 기반이며, 실제 도보·지하철 최단 경로를 계산하는 방식은 아닙니다.

## 로컬 실행

### 1. 백엔드 준비

Node.js와 npm이 필요합니다. 백엔드는 전역 `fetch`를 사용하므로 이를 지원하는 Node.js 환경을 사용합니다. 아래 명령은 저장소 루트에서 실행합니다.

```powershell
npm install
```

필요하면 `.env`에 다음 값을 설정합니다.

```dotenv
PORT=8080
SHEET_CSV_URL=여기에_접근_가능한_Google_Sheets_CSV_URL_입력
```

`PORT` 기본값은 `8080`이며, `SHEET_CSV_URL`을 생략하면 코드에 지정된 기본 시트 URL을 사용합니다. 직접 시트를 지정할 때는 로그인 없이 CSV를 읽을 수 있는 주소를 사용해야 합니다.

### 2. 장소 데이터 준비

CSV 첫 행은 다음 열 이름을 기준으로 작성합니다.

| 열 이름 | 용도 |
| --- | --- |
| `id (고유번호)` | 장소 식별과 코스 간 중복 제외 |
| `name (이름)` | 화면과 지도에 표시할 이름 |
| `category (카테고리)` | 식당, 카페, 소품샵 분류 |
| `address (주소)` | 지역 문자열 필터링 |
| `latitude (위도)` | 위치 표시와 거리 계산 |
| `longitude (경도)` | 위치 표시와 거리 계산 |
| `weather (날씨)` | 선택 날씨에 따른 추천 점수 |

추가 열의 내용도 전체 텍스트로 합쳐져 동행 유형·날씨 관련 키워드 점수에 사용됩니다. 데이터에는 서로 다른 장소 ID와 유효한 좌표를 넣고, 지역마다 카테고리별 장소를 충분히 확보합니다. 서버는 파싱·필터링 후 전체 장소가 3개 미만이면 시작하지 않습니다.

### 3. 서버 시작

```powershell
npm run dev
```

데이터 로딩이 성공하면 `http://localhost:8080`에서 백엔드가 실행됩니다. 데이터는 서버 시작 시 읽어 메모리에 저장하므로 시트를 수정한 뒤에는 서버를 재시작해야 반영됩니다.

### 4. 프론트엔드 열기

1. `frontend/`를 정적 HTTP 서버로 제공합니다. 예를 들어 VS Code의 Live Server를 사용할 수 있습니다.
2. 해당 서버에서 `page1/index.html`을 엽니다.
3. `frontend/map.html`의 Kakao Maps SDK `appkey` 설정을 확인합니다. 사용할 JavaScript 키와 로컬 서비스 주소에 맞는 도메인 설정이 필요합니다.
4. 지역·동행 유형·날씨를 선택하고 검색합니다.

백엔드는 HTML 정적 파일을 제공하지 않으므로 프론트엔드용 서버가 별도로 필요합니다. 프론트엔드의 API 주소는 `http://localhost:8080`으로 고정되어 있습니다. 백엔드 포트를 변경하면 `frontend/page2/main.js`와 `frontend/map.html`의 요청 주소도 함께 수정해야 합니다.

## API

`src/app.ts` 기준입니다.

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/` | 서버 실행 확인용 텍스트 반환 |
| GET | `/api/locations` | `{ count, locations }` 형태로 장소 데이터 반환 |
| GET | `/api/recommend-course` | `{ companion, weather, courses }` 형태로 추천 결과 반환 |

추천 요청 예시:

```text
/api/recommend-course?region=수영구&companion=가족&weather=비
```

| 쿼리 | 허용 값·동작 |
| --- | --- |
| `region` | 주소에 포함되는 문자열. 화면은 광안리 → `수영구`, 해운대 → `해운대구`, 서면 → `서면`을 전달. 생략하면 전체 지역 대상 |
| `companion` | `가족`, `연인`, `데이트`, `친구`, `혼자`. 현재 화면에는 가족·연인·친구만 노출 |
| `weather` | `맑음`, `비`, `폭염` |

동행 유형이나 날씨 값이 올바르지 않으면 HTTP `400`, 추천 생성 중 오류가 발생하면 HTTP `500`을 반환합니다. 각 추천 장소에는 `order`, `score`, `recommendationReasons`, `distanceFromPreviousKm` 등이 포함됩니다.

## 현재 제약과 다음 개발 단계

- **지하철 연결:** 부산역 출발 경로, 노선·환승·출구 데이터와 관광 장소를 연결해야 합니다.
- **실제 이동 경로:** 지도 연결선은 장소 좌표를 이은 선입니다. 도보 경로, 지하철 경로, 이동 소요 시간은 아직 제공하지 않습니다.
- **지역 매칭:** 주소 문자열로 지역을 찾기 때문에 `서면`이라는 단어가 없는 주소는 서면 검색에서 제외될 수 있습니다.
- **지도 표시 연동:** 추천 응답을 받은 뒤 iframe의 `onload`를 등록하므로, 지도가 먼저 로드되면 코스 전달이 누락될 가능성이 있습니다. 지도 준비 완료와 데이터 수신을 안정적으로 연결하는 처리가 필요합니다.
- **추천 기준 정비:** 현재 비 오는 날 추천에는 주차 관련 가산점도 있어, 지하철 중심의 기획에 맞게 기준을 조정할 필요가 있습니다.
- **시간대 반영:** 방문 가능 시간, 체류 시간, 노을과 행사 일정 데이터를 추가해야 합니다.
- **개인 일정:** 장소 저장, 선택 코스 확정, 저장 장소 기반 경로 생성과 후속 화면을 구현해야 합니다.

## 팀 활동 방식

1. 밥집·카페·관광지 등 조사할 장소를 함께 결정합니다.
2. 조사 장소를 정한 후 팀을 무작위로 배정합니다.
3. 일정에 따라 참여 가능한 인원끼리 유동적으로 팀을 구성합니다.
4. 현장 조사에서는 환승 위치, 출구, 도보 동선과 장소별 방문 조건을 기록해 서비스 데이터에 반영합니다.

이 문서는 프로젝트 기획과 커밋된 소스 확인을 바탕으로 작성했습니다. 외부 시트 접근, 지도 키 설정, 브라우저에서의 실제 동작 검증은 별도로 필요합니다.
