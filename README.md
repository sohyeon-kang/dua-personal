# DUA — 부산 지하철 여행 도우미

> 어디로든 떠나고 싶은 순간, 부산이 답합니다.

DUA는 **부산을 처음 방문하는 국내 여행객을 위한 지하철 중심 여행 서비스**를 목표로 하는 프로젝트입니다. 부산역을 출발 거점으로 삼아 지하철 이동, 환승과 출구 안내, 맛집과 관광지 추천을 하나의 여행 동선으로 연결하고자 합니다.

현재 코드는 **지역·동행 유형·날씨에 따른 장소 추천과 지도 표시를 구현한 웹 프로토타입**입니다. 모바일 화면에서 코스·장소 저장과 선택 순서에 따른 구간별 도보 길찾기를 제공합니다. 지하철 길찾기와 시간대별 추천은 향후 구현할 기능입니다.

## 기획 배경

초행 여행객은 목적지까지 가는 방법뿐 아니라, 이동 과정에서 무엇을 확인해야 하는지와 도착 후 어디를 방문할지도 함께 알아야 합니다. 이 프로젝트는 다음과 같은 불편을 해결하는 데서 출발했습니다.

| 구분 | 해결하고자 하는 불편 |
| --- | --- |
| 지하철 이용 | 환승 위치와 빠른 환승 정보가 부족해 이동이 어려움 |
| 출구 선택 | 관광지와 가까운 출구와 출구 이후의 경로를 파악하기 어려움 |
| 열차 운행 이해 | 급행·일반, 직행 여부, 중간 종착에 따른 하차와 재승차 안내가 필요함 |
| 관광지 탐색 | 여행 조건에 맞는 맛집·카페·명소를 찾기 번거로움 |
| 일정 구성 | 방문할 장소의 순서와 이동 동선을 직접 정해야 함 |

위 내용은 프로젝트의 문제의식이며, 특정 지도·도시철도 앱의 기능을 검증한 비교 결과는 아닙니다.

## 대상과 활동 범위

- **대상:** 부산이 낯선 국내 여행객. 초기 기획에서는 외국인 대상 다국어 기능을 범위에 포함하지 않습니다.
- **지역:** 서면, 광안리, 해운대 등 부산의 주요 관광 거점.
- **이동 기준:** 부산역을 출발 거점으로 하는 지하철 이동과 출구 이후 도보 연결.
- **교통수단:** 지하철 중심으로 구성하며 버스 경로는 초기 범위에서 제외합니다.
- **장소:** 팀에서 함께 선정한 식당, 카페, 관광지 등을 조사하고 추천 데이터로 정리합니다.

## 목표 기능

| 기능 | 제공하려는 정보와 경험 |
| --- | --- |
| 열차 이용 안내 | 적용 대상 노선의 급행·일반 구분, 직행 여부, 중간 종착 시 하차·재승차 설명 |
| 빠른 환승 안내 | `8-1`과 같은 승강장 탑승 위치를 기준으로 환승 경로 안내 |
| 출구 중심 경로 | 목적지와 가까운 출구와 출구에서 추천 장소까지의 도보 경로 제공 |
| 관광 코스 추천 | 맛집·카페·명소를 방문 순서와 함께 추천 |
| 시간대 기반 추천 | 노을 감상, 드론쇼 등 방문 시각이 중요한 활동을 일정에 반영 |
| 개인 맞춤 동선 | 사용자가 가고 싶은 장소를 저장하면 해당 장소를 연결하는 경로 생성 |

열차 유형과 운행 안내는 실제 서비스 대상 노선에 해당하는지 확인한 뒤 적용합니다. 행사 일정과 운영 정보 역시 확인된 데이터를 바탕으로 반영할 예정입니다.

## 차별화 방향

기존 지도·도시철도 앱과 비교할 때 DUA가 지향하는 차별점은 **여행 일정과 지하철 이동을 함께 설계하는 경험**입니다.

- **여행 중심 정보:** 이동 안내에 환승 위치, 출구, 주변 관광 정보를 함께 제공합니다.
- **이동과 관광의 연결:** 부산역에서 관광 지역으로 이동하고, 출구에서 개별 장소까지 이어지는 동선을 구성합니다.
- **시간과 상황 반영:** 동행 유형·날씨에 더해 방문 시간과 행사 일정을 추천에 반영합니다.
- **사용자가 선택하는 여행:** 추천 코스를 비교하거나 가고 싶은 장소를 저장해 자신의 일정을 구성하도록 합니다.

## 현재 구현 상태

기본 주소 `/`는 새 모바일 디자인 `/mobile/page1/`로 연결됩니다. 여행 조건 → 추천 코스 → 이동 안내 → 저장의 네 화면을 제공하며, 기존 화면은 `/page1/`에서 볼 수 있습니다. 모바일 디자인의 상세 범위는 [모바일 README](frontend/mobile/README.md)를 참고하세요.

모바일 화면은 기존 DUA 로고와 청록색 지하철 모티브를 사용합니다. 코스 A·B·C 선택에 따라 방문 순서 1·2·3의 색상도 통일됩니다. 시간대는 오전·오후 메모로만 보관하며, 백엔드에서 제공하지 않는 예상 시간은 표시하지 않습니다. 지하철·환승·출구 정보는 연결 전입니다.

| 항목 | 현재 동작 |
| --- | --- |
| 검색·조건 변경 | 지역·동행·날씨 검증, 이전 선택 복원 |
| 추천 | 지역별 최대 3개 완성 코스, 코스 간 장소 중복 제외, 부족한 데이터 안내 |
| 코스 선택·상세 | 방문 순서, 주소, 항목별 이용 정보, 길찾기, 텍스트 복사 |
| 상태 유지 | 같은 탭의 새로고침과 페이지 이동 시 선택 코스 복원 |
| 지도 | 준비 완료 메시지로 경로·선택 동기화, 실패 시 외부 지도 링크 제공 |
| 실행 | Express에서 페이지와 API를 함께 제공 |
| 검증 | TypeScript 검사, API·추천·상태 복원 테스트, 실제 데이터로 브라우저 흐름 확인 |

## 실행

Node.js 22 이상에서 프로젝트 폴더를 열고 실행합니다.

```powershell
npm ci
npm run dev
```

브라우저에서 <http://localhost:8080>을 엽니다. 프론트엔드와 API를 같은 서버에서 제공합니다. HTML 파일을 직접 열거나 별도의 Live Server로 실행하지 않아도 됩니다. 기본 서버는 개인 작업용으로 이 컴퓨터에서만 접근할 수 있습니다.

빌드한 버전으로 실행하려면 `npm run build` 후 `npm start`를 사용합니다. 검증은 `npm test`, 타입 검사는 `npm run typecheck`입니다.

## 사용 흐름

1. 지역, 동행 유형, 날씨를 선택하고 검색합니다.
2. 최대 3개의 추천 코스를 탭으로 비교하고 **코스 선택**을 누릅니다.
3. 상세 페이지에서 방문 순서, 주소, 항목별로 정리한 이용 정보와 카카오맵 길찾기를 확인합니다. 이미 선택한 날씨·동행 조건에 관한 추천 문구는 장소마다 반복하지 않습니다.
4. **추천 코스로 돌아가기**, **조건 변경**, **다시 추천받기**로 이어서 탐색할 수 있습니다. 코스 내용 복사는 텍스트와 길찾기 주소를 클립보드로 복사합니다.

검색 결과와 선택한 코스는 브라우저 탭의 sessionStorage에 저장되어 새로고침과 페이지 이동 시 유지됩니다. 모바일 화면에서 북마크한 코스와 장소는 localStorage에 별도로 보관하므로 탭을 닫아도 유지됩니다. 계정 간 동기화는 지원하지 않으며 브라우저 데이터를 삭제하면 사라집니다. 저장소가 차단되면 안내가 표시됩니다.

## 데이터와 지도

- 기본 Google Sheets를 읽기 전용으로 가져오며 5분간 캐시합니다. 시트를 수정하거나 테스트 데이터를 실제 결과에 섞지 않습니다.
- 각 코스는 식당 → 카페 → 소품샵 순서입니다. 서로 다른 코스 간에도 장소를 중복하지 않습니다. 카테고리별 장소가 부족하면 완성 가능한 코스만 표시합니다.
- 서면은 주소의 부산진구·전포동·부전동·서면을 함께 검색합니다. 데이터에 없는 지역이나 이용 정보는 임의로 만들지 않습니다.
- 지도 선과 거리 합계는 직선 기준입니다. 실제 경로와 소요 시간은 카카오맵 길찾기에서 확인합니다.
- 지도 SDK 연결이 실패해도 추천·상세 내용과 외부 길찾기를 사용할 수 있습니다.

설정이 필요하면 `.env.example`을 `.env`로 복사합니다. `.env`는 Git에서 제외됩니다.

| 설정 | 용도 |
| --- | --- |
| `PORT` | 로컬 실행 포트, 기본 8080 |
| `SHEET_CSV_URL` | 같은 열 구조를 가진 Google Sheets CSV 주소. 빈 값이면 기존 시트 사용 |
| `KAKAO_MAP_APP_KEY` | 카카오 JavaScript SDK 키. 생략하면 기존 프로젝트 키 사용 |

카카오 키를 바꾸거나 포트를 바꾸면 [카카오 개발자 설정](https://apis.map.kakao.com/web/guide/)에서 해당 키의 JavaScript SDK 도메인에 실행 주소(예: `http://localhost:8080`)를 등록해야 합니다. 서버용 REST API 키를 넣지 마세요. 브라우저용 JavaScript 키는 클라이언트에 전달됩니다.

### 개인 카카오 지도 연결

1. 카카오 Developers에서 생성한 앱의 **카카오맵 → 사용 설정 → 상태 ON**을 설정합니다.
2. **앱 → 플랫폼 키 → JavaScript 키 → JavaScript SDK 도메인**에 `http://localhost:8080`, `http://127.0.0.1:8080`을 각각 한 번씩 등록하고 저장합니다. `/mobile/` 같은 경로는 붙이지 않습니다.
3. 프로젝트 루트의 `.env`에 `KAKAO_MAP_APP_KEY=발급받은_JavaScript_키`를 설정합니다.
4. 서버를 재시작하고 모바일 추천 코스 화면에서 지도를 확인합니다.

`401 domain mismatched` 응답은 사용 중인 키에 등록된 도메인과 접속 주소가 다르다는 뜻입니다. 해당 키의 도메인 설정과 저장 여부를 확인하세요. 저장소에는 개인 `.env`, 로컬 진단 스크립트와 실행 결과를 포함하지 않습니다.

개인 수정본은 개인 Private 저장소에서 관리합니다. 팀 프로젝트에 공유할 시점에 변경 사항을 별도 브랜치로 옮겨 검토하면 됩니다.

## API와 CSV 구조

| 경로 | 동작 |
| --- | --- |
| GET / | 검색 화면으로 이동 |
| GET /api/health | 서버 상태 |
| GET /api/config | 공개용 카카오 JavaScript 키 |
| GET /api/locations | 장소 목록. region 쿼리로 지역 필터 가능 |
| GET /api/recommend-course | region, companion, weather를 받아 courses와 안내 message 반환 |

추천 필터는 지역(수영구/광안리, 해운대구/해운대, 서면/부산진구), 동행(가족, 연인/데이트, 친구, 혼자), 날씨(맑음, 비, 폭염)입니다. 화면의 동행 선택은 기존의 가족·연인·친구를 유지합니다. 필터 오류는 400, 외부 장소 데이터 연결 오류는 503, 데이터 부족은 200과 빈 courses/안내 문구로 구분합니다.

CSV 필수 열: id (고유번호), name (이름), address (주소), latitude (위도), longitude (경도), category (카테고리).

선택 열: weather (날씨), access (이동/접근성), parking (주차), waiting (웨이팅), kids (키즈존/아기), seat (이용/좌석), view (분위기/뷰). 헤더 공백과 소품샵 오타를 정규화하고, 중복 ID·빈 좌표·유효 범위 밖 좌표를 제외합니다.

추천은 동행·날씨 키워드 점수와 이전 장소부터의 직선거리를 사용합니다. 최상위 점수와 차이가 2점 이내인 최대 6개 후보 중 무작위로 선택하므로 같은 조건의 결과가 달라질 수 있습니다. 지하철·실제 도보 최단 경로를 자체 계산하는 방식은 아닙니다.

## 팀 활동 방식

1. 밥집·카페·관광지 등 조사할 장소를 함께 결정합니다.
2. 조사 장소를 정한 후 팀을 무작위로 배정합니다.
3. 일정에 따라 참여 가능한 인원끼리 유동적으로 팀을 구성합니다.
4. 현장 조사에서는 환승 위치, 출구, 도보 동선과 장소별 방문 조건을 기록해 서비스 데이터에 반영합니다.
